## 1. Стек (один вариант)
**React Native + Expo + TypeScript.** Один код работает и на iPhone, и на Android. На телефоне приложение открывается бесплатной программой Expo Go без установки Xcode и Android Studio, что для новичка проще всего. TypeScript ловит ошибки ещё до запуска, а проверки (тесты, линтер) я запускаю сам.

Состав: Expo Router (экраны), `expo-video` (воспроизведение), `expo-image-picker` (выбор видео из галереи), `expo-sqlite` (хранение на телефоне), Jest + React Native Testing Library (тесты), ESLint + Prettier, `react-native-web` (только чтобы я мог проверять экраны в браузере скриншотами).

**Альтернативы кратко:** Flutter (хорош, но другой язык Dart, меньше готовых материалов в этом репозитории); нативная разработка Swift + Kotlin (в два раза больше работы); PWA/сайт (хуже для видео-ленты и магазинов приложений).

## 2. Функции MVP (v1)
1. Вертикальная лента коротких видео со свайпом, автозапуском, паузой по касанию.
2. Лайки, просмотры, счётчики.
3. Загрузка своего видео из галереи: длина и размер ограничены, название, тег-тренд, **обязательная отметка «создано ИИ / не создано ИИ»**, возрастная метка.
4. «Волны» (тренды как монеты): список, карточка, индекс тренда и график. Индекс считается из просмотров и лайков видео с этим тегом.
5. «Искры» (виртуальные баллы): стартовый баланс, история операций. Они ничего не стоят, и это написано в интерфейсе.
6. Прогноз роста волны: поставить искры на «вырастет за 24 ч», расчёт по итогам, начисление или списание искр. В тексте интерфейса слово «ставка» не используем.
7. Жалобы на видео, скрытие, фильтр запрещённых слов, статусы «на проверке / опубликовано / отклонено».
8. Онбординг: подтверждение 18+ (самоподтверждение), согласие на обработку данных (текст-заготовка для юриста), правила, удаление всех своих данных одной кнопкой.
9. Профиль с локальным никнеймом и своими видео.
10. Интерфейс полностью на русском; тексты вынесены в один файл, чтобы их легко править.

**Откладываем (не делаем в v1):** реальные деньги, ставки, пополнение, вывод, крипта; регистрация по телефону/почте и вход через сервисы; сервер и облако; комментарии, подписки, личные сообщения; push-уведомления; рейтинг игроков; запись и монтаж видео в приложении; генерация ИИ-видео внутри приложения; реклама; поиск; автоматическая ИИ-модерация; админ-панель; публикация в App Store / Google Play / RuStore; веб-версия.

## 4. Заделы на будущее (без лишнего кода)
- Всё обращение к данным идёт через интерфейсы-репозитории (`VideoRepository`, `TrendRepository`, `WalletRepository`, …). Сегодня за ними хранилище на телефоне, потом заменим на российский сервер без переписывания экранов.
- Кошелёк реализован как журнал операций (ledger): записи только добавляются, баланс = сумма записей, у записи есть поле «вид актива», сейчас единственное значение `POINTS`. Реальные деньги и платёжного провайдера мы НЕ пишем, но дверь для них остаётся.

## 6. Как увидеть приложение на вашем телефоне
Первый раз — на этапе 1, я заранее скажу, что нужно сделать.
1. Установите на телефон **Expo Go** (iPhone — App Store; Android — Google Play, а если он недоступен, то APK с официального сайта expo.dev/go).

## 9. Известные ограничения прогнозов (этап 8): для юриста и серверной версии

Это не ошибки, а особенности демо-версии без сервера. Их нужно решить до публичного запуска и перенести в `docs/LEGAL-CHECKLIST.md` на этапе 13.

1. **Влияние на собственный индекс.** Пока в приложении один пользователь, он сам своими просмотрами и лайками двигает индекс волны. «Поддержать волну» и тут же поставить лайк в этой волне почти гарантированно даёт ×2. В настоящей игре индекс должен складываться из действий многих людей, плюс нужны ограничения (задержка, суточный лимит, исключение действий самого участника).
2. **Итог считается в момент первой загрузки после срока, а не ровно в срок.** Результат сравнивается по состоянию индекса в тот момент, когда пользователь открыл кошелёк, карточку волны или список прогнозов. Можно «подгадать» момент. Серверная версия должна закрывать прогноз ровно в срок и по зафиксированному значению.
3. **Нет единой транзакции при открытии прогноза.** Искры списываются, затем прогноз сохраняется; при ошибке выполняется возврат, но при внезапном закрытии приложения ровно между двумя записями искры могут «зависнуть». Решается транзакцией в базе (на сервере) или восстановлением при следующем запуске.
4. **Возврат помечен как «Итог прогноза».** Отдельного вида записи для возврата нет (потребует миграции схемы).
5. **Юридический вопрос по существу:** не подпадает ли механика «искры + прогноз на рост + двойная выплата или потеря» под регулирование азартных игр, пари и лотерей, даже при отсутствии стоимости у искр. См. раздел 7.
